### 柏林噪声可视化

柏林函数本质上就是在一个2D灰度图中取灰度值。
通过输入一个2D坐标（x, y），返回该位置的灰度值（0~1）float。

柏林噪声的核心特性：**空间连续性**——相邻坐标的值一定相近，不会突变。这是它和纯随机噪声最大的区别
如果每次柏林函数取值的差值相等，柏林噪声的过渡会更平滑，这是它的特性决定的

1. 非柏林噪声的随机数 (`i * 0.1f`, `Random.value(0~1)`, `0`) 可以看到 非常生硬
![[Pasted image 20260609011948.png]]

```csharp
Vector3[] posArr = new Vector3[100];
for (int i = 0; i < posArr.Length; i++)
    posArr[i] = new Vector3(i * 0.1f, Random.value, 0);
lineRenderer.SetPositions(posArr);
```

2. 柏林噪声生成的随机数 (`i * 0.1f`, `Mathf.PerlinNoise(i * a, i * a)`, `0`) 
 ![[Pasted image 20260609012908.png]]

```csharp
posArr[i] = new Vector3(i * 0.1f, Mathf.PerlinNoise(i * a, i * a), 0);
```

优化柏林噪声，实现伪随机效果，让每一次生成的曲线不一样
其实就是让柏林噪声的函数x和y随机偏移就行了

![[Pasted image 20260609013731.png]]

```csharp
float ranX = Random.Range(1, 1000);
float ranY = Random.Range(1, 1000);

posArr[i] = new Vector3(i * 0.1f, Mathf.PerlinNoise(i * a + ranX, i * a + ranY), 0);
```

CheckRotation：
- 确定方向，如果旋转灯，方向为right，如果旋转地图，方向为forward
- 得到当前小车的旋转量，如果左转需要额外处理。
- Rotate 方向 * -速度(因为车左转，地图右转) * 车转向比例（carRotation/rotateAngle）* 每间隔对应角度的1/10 * 时间

```csharp
private void CheckRotation()
{
    Vector3 dir = (lamp) ? transform.right : transform.forward;
    float carRotation = carTransform.localEulerAngles.y;//得到当前旋转欧拉角的y值
    if (carRotation > car.rotateAngle * 2f) //判断是否是左转 左转的欧拉角（360 - rotateAngle）一定大于 car.rotateAngle * 2f
        carRotation = (360 - carRotation) * -1f;
    //方向 * -rotateSpeed * 旋转幅度系数 * 旋转速度系数(360 / 10 / x轴顶点间隔数量) * 时间
    transform.Rotate(dir * -rotateSpeed * (carRotation / (float)car.rotateAngle * (36f / worldGenerator.dimensions.x) * Time.deltaTime));
}
```

#### Mesh核心概念：顶点、三角形、UV

**顶点 vertices（Vector3）** 网格中每个点在3D世界空间中的坐标，是构成网格的最小单位。

**UV（Vector2）** 每个顶点对应贴图上的采样位置。贴图被归一化为0~1的正方形，U是横向，V是纵向。UV和顶点一一对应，`vertices[i]` 对应 `uvs[i]`。UV与顶点的世界坐标完全独立，顶点移动不影响UV。

**三角形 triangles（int[]）** 存储的是顶点的索引，每3个索引描述一个三角形。顶点可以被多个三角形复用。三个顶点从观察者角度看**顺时针排列 = 正面可见，逆时针 = 背面不可见**。决定法线方向的是三个顶点在空间中呈现的绕向，与哪个点作为起点无关。

#### 生成逻辑与数学计算

---

##### 一些关键数据

**二维：**
countX：x轴顶点间隔的数量
countZ：z轴顶点间隔的数量
scale：顶点与顶点之间的距离
**注意：UV对应的是二维，所以顶点移动每次只需要加 scale 就行**

**三维：**
radius：半径 = x轴的长度 / 2 = countX * scale * 0.5f
周长 = 2πr = countX * scale * π
两个顶点之间的距离 = 顶点间隔的弧长 = 周长 / 顶点间隔数量 = countX * scale * π / countX  = scale * π
**注意：顶点对应的是三维，所以顶点移动每次需要加 scale * π**

---

##### 初始化顶点和UV

**1. 初始化顶点和UV顶点的数量：**
因为countX代表的是间隔，所以需要加1

```csharp
vertices = new Vector3[(countX + 1) * (countZ + 1)];
uvs = new Vector2[(countX + 1) * (countZ + 1)];
```

---

**2. 初始化顶点和UV：**
**一些关键数据：**
rad：当前顶点与圆心夹角的弧度 = 360° * 当前顶点索引与顶点总数的比值 = 2π * x * scale / (countX * scale) = 2 * π * x  / countX
邻边 即 x轴坐标 = cos(rad) * radius
对边 即 y轴坐标 = sin(rad) * radius
z轴坐标 = 当前z轴顶点 * 间隔距离 = z * scale * π

```csharp
for (int x = 0; x <= countX; x++) //双循环设置顶点和UV
{
    for (int z = 0; z <= countZ; z++) 
    {
        float rad = 2f * Mathf.PI * x / countX;//得出弧度
        vertices[index] = new Vector3(Mathf.Cos(rad) * radius, Mathf.Sin(rad) * radius, z * Mathf.PI * scale);//初始化顶点
        uvs[index] = new Vector2(x * scale, z * scale);//初始化UV
        ++index;
    }
}
//外层循环每走一步，生成的是圆柱面上的一条"竖线"，而不是孤立的点
```

**注意：UV绘制的过程和顶点一一对应，完全一致，唯一区别就是，顶点间隔由3D间隔变成2D间隔**

**3. 在顶点和UV的生成中引入柏林噪声**

**柏林噪声引入目的：**
让圆柱面产生随机平滑的凹凸效果，模拟自然地形起伏。

**采样坐标的选择（pX / pY）：**
用当前顶点的 x 和 z 世界坐标作为柏林函数的输入坐标。
原因：顶点之间的空间间距是固定的，对应的采样坐标间距也固定，柏林噪声的空间连续性保证了凹凸过渡平滑自然。`perlinScale` 控制采样间距的缩放——值小则地形平缓，值大则地形崎岖。`offset` 平移采样区域，实现伪随机换种效果。

**内凹方向的计算：**
直接给顶点坐标加噪声值会向外凸，需要反向。做法是找到当前圆截面的圆心 `center = (0, 0, vertices[index].z)`，计算顶点指向圆心的向量并归一化，得到纯方向向量。

**最终位移计算：**

```
移动量 = (center - vertex).normalized × PerlinNoise(pX, pY) × waveHeight
```

噪声值范围 0~1，所以实际内凹距离在 0~waveHeight 之间。噪声值大的顶点内凹多，噪声值小的几乎不动，整体形成平滑的随机凹凸地形。`waveHeight` 可在外部手动控制起伏幅度。

```csharp
//柏林噪声的引入
float pX = (vertices[index].x * perlinScale) + offset;
float pY = (vertices[index].z * perlinScale) + offset;
//计算顶点到圆心的方向 然后 乘以 取到的灰度值 乘以 起伏幅度
Vector3 center = new Vector3(0, 0, vertices[index].z);
vertices[index] += (center - vertices[index].normalized * Mathf.PerlinNoise(pX, pY) * waveHeight);
```

##### 初始化三角形数组

**数量初始化：**

```csharp
triangles = new int[countX * countZ * 6];
```

`countX * countZ` 是矩形总数（x方向间隔数 × z方向间隔数），每个矩形由2个三角形组成共6个索引，所以总长度是矩形数 × 6。

**boxBase 的构成**

每次外层循环取相邻两列（x列和x+1列）的前两个顶点，构成一个矩形的6个索引：

```
x*(countZ+1)        → x列第1个顶点
x*(countZ+1)+1      → x列第2个顶点
(x+1)*(countZ+1)    → x+1列第1个顶点
x*(countZ+1)+1      → x列第2个顶点
(x+1)*(countZ+1)+1  → x+1列第2个顶点
(x+1)*(countZ+1)    → x+1列第1个顶点
```

绕序是**逆时针**，法线朝内——因为这是隧道，玩家在圆柱内侧观察。

**内层循环逐格平移**
每次内层循环先把 boxBase 所有值 +1（整体下移一格），再写入 triangles 时 -1 取回当前格。等价写法是先写入再 +1，可以省去 -1：

```csharp
//初始化三角形
triangles = new int[countX * countZ * 6];//矩形总数 * 每个矩形的节点数
//创建一个数组 存6个顶点，方便调用
int[] boxBase = new int[6];
int current = 0;//三角形顶点的索引
for (int x = 0; x < countX; x++) 
{
    //为存顶点索引的数组初始化
    boxBase = new int[] 
    {
        x * (countZ + 1),
        x * (countZ + 1) + 1,
        (x + 1) * (countZ + 1),
        x * (countZ + 1) + 1,
        (x + 1) * (countZ + 1) + 1,
        (x + 1) * (countZ + 1),
    };

    for (int z = 0; z < countZ; z++)
    {
        //把6个顶点填充到三角形顶点的数组中去
        for (int j = 0; j < 6; j++)
            triangles[current + j] = boxBase[j] - 1;
        //把存顶点索引的数组移动到下一个矩形
        for (int i = 0; i < 6; i++)
            boxBase[i] = boxBase[i] + 1;
        current += 6;
    }
}
```

#### 实现无尽地图

核心逻辑就是生成两个地图块，当第一个地图块移动到末尾，就销毁它。然后在第二个地图块前面接上生成，然后走到第二个地图块末尾，销毁它，在新生成的第一个地图重新生成前面接上。循环就可以达到无尽的效果

---

#### 首尾衔接优化

目的是让新地图块的起始边和上一块末尾边平滑衔接，避免接缝处出现裂缝或摄像机穿模。

---

**存储末尾顶点**

每块地图生成时，当 `z == countZ`（最后一圈顶点）时，把该顶点存入 `beginPoints[x]`，供下一块地图衔接使用。

---

**过渡区插值**

新地图块生成时，在 `z < startTransitionLength` 且 `beginPoints[0] != Vector3.zero`（非第一次生成）的范围内，对顶点做插值：

```csharp
float perlinPercentage = z * (1f / startTransitionLength);
Vector3 beginPoint = new Vector3(beginPoints[x].x, beginPoints[x].y, vertices[index].z);
vertices[index] = Vector3.Lerp(beginPoint, vertices[index], perlinPercentage);
```

- `beginPoint` 的 xy 取上一块末尾顶点的截面坐标，z 取当前顶点自己的 z（保证深度正确）
- `perlinPercentage` 是当前 z 在过渡区里的进度比例（0→1）
- `Lerp` 从 `beginPoint` 匀速过渡到噪声顶点，过渡区结束后完全变成正常的柏林噪声地形

**第一次生成不受影响**

`beginPoints` 初始全为 `Vector3.zero`，条件 `beginPoints[0] != Vector3.zero` 不满足，第一块地图正常生成，无过渡处理。

### GameManager：管理游戏逻辑、UI
