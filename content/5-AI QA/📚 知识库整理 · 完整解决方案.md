### 第一步：先回答最关键的问题——要不要迁移到 Obsidian？

#### 诊断你的情况

你描述的问题核心不是"用哪个软件"，而是：

> **笔记分散 → 找不到 → 不愿意看 → 继续分散** 的恶性循环

Obsidian 能解决这个问题吗？**能，但有前提。**

|你的担心|真相|
|---|---|
|怕做无效搬运|✅ 合理，盲目搬运确实是坟场的第一步|
|刚接触不知下手|✅ 需要先建好结构再迁移，顺序很重要|
|想完全统一|⚠️ "完全统一"本身就是陷阱，先明确哪些值得统一|

**结论：可以迁移到 Obsidian，但不是现在，先做这三件事：**

### 第二步：迁移前必须做的事

#### 🔍 第一件事：做一次"笔记审计"

先不要动任何笔记，花 1 小时回答这几个问题：

```
幕布里的基础知识点  → 我最近 3 个月查阅过几次？
语雀里的练习题      → 我还会回头看吗？
OneNote 的计划表    → 这是归档还是在用？
```

**判断标准：**

- 近 3 个月没看过 → 大概率不需要搬，归档即可
- 经常查阅 → 值得搬
- 练习题答案 → 重新做一遍比搬运更有价值

---

#### 🏗️ 第二件事：先建好 Obsidian 的结构，再搬内容

很多人失败的原因是：**把旧笔记的混乱复制进了新软件。**

推荐给你一套适合程序员的结构：

```
📁 00-收件箱 (Inbox)
   └── 随手记，还没整理的想法、链接、摘录

📁 01-项目 (Projects)
   └── 正在进行的具体项目（有开始有结束）
   └── 比如：学完 Python 基础、做完 XX 练习

📁 02-知识库 (Knowledge)
   ├── 编程/
   │   ├── Python/
   │   ├── 数据结构/
   │   └── 算法/
   └── 工具/
       └── Git、Linux...

📁 03-资源 (Resources)
   └── 书单、课程笔记、参考资料（可以放练习题）

📁 04-归档 (Archive)
   └── 已完成项目、旧笔记的静态备份
```

> **核心原则：** 收件箱是唯一入口，所有新笔记先进收件箱，整理后再归类。

---

#### ✍️ 第三件事：学会正确的记笔记方式（比搬运更重要）

**你现在的笔记很可能是"摘抄"而不是"理解"**

```
❌ 坟场笔记："列表推导式：[x for x in list if condition]"

✅ 活笔记：
   ## 列表推导式
   **我的理解**：就是把 for 循环压缩成一行
   **什么时候用**：想生成新列表、过滤数据时
   **我踩过的坑**：条件写反了导致结果为空
   **例子**（我自己写的）：
   even = [x for x in range(10) if x % 2 == 0]
   **关联**：[[for循环]] [[filter函数]]
```

**记笔记的黄金标准 → 用自己的话写，能关联，能被未来的自己看懂**

### 第三步：笔记快速搬运方法

#### 各平台导出方式

| 平台      | 导出格式        | 操作                              |
| ------- | ----------- | ------------------------------- |
| 幕布      | 导出 Markdown | 菜单 → 导出 → .md 格式，可直接放入 Obsidian |
| 语雀      | 导出 Markdown | 知识库设置 → 导出，支持批量                 |
| OneNote | 较麻烦         | 建议用 OneNote Exporter 工具导出为 .md  |

**搬运的正确姿势：**

```
❌ 错误：把所有笔记一次性全部导入
✅ 正确：
   第一步 → 只导入你最常用的 20% 内容
   第二步 → 导入后重新整理，不是直接粘贴
   第三步 → 旧平台保留作为"冷存储"，不急着删
```

---

### 第四步：Obsidian 最值得学的 3 个功能

先不要装太多插件，掌握这三个核心就够用：

**1. 双向链接 `[[]]`**

> 写笔记时提到某个概念，直接 `[[概念名]]` 关联， 这是 Obsidian 最核心的能力，让笔记互相"认识"

**2. 图谱视图**

> 可以看到你所有笔记的关联网络， 孤立的节点 = 死笔记，多连接的节点 = 核心知识点

**3. 模板（Templates）**

> 给不同类型笔记建模板，比如"编程知识点模板" 每次记笔记直接套，保持格式统一
