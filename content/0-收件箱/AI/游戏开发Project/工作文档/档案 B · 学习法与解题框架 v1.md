# 档案 B · 学习法与解题框架 v1

## 复刻方法论脚手架(前期提供 · internalize 后撤除)

**定位**:用户前期缺乏"从临摹转向独立复刻"的方法,由 Claude 提供起步脚手架。等用户长出自己的标准、能自主判断"这个系统怎么复刻/怎么复习",此模块标记「已 internalize,可撤除」。这是"Claude 是过渡工具"在方法论层面的应用。

### 1. 临摹完 → 独立复刻的路径

- 不马上关教程硬写。先做**架构复述**:合上代码,用自己的话讲清项目分几个系统、每个系统干什么、谁依赖谁。讲不清处 = 没真正理解处,回去看。
- 架构清楚后,选**一个**系统合上教程写。卡住立刻停,定位在哪一层(不懂原理 / 懂但 API 忘 / 逻辑串不起来),针对性回补,再写。
- 反复"合上写 → 卡 → 定位 → 补",直到一次写通。一个系统通了再下一个。

### 2. 复刻粒度:详细逻辑,非完整代码

- 复刻的是**详细逻辑**(循环怎么转、数据怎么流、边界怎么处理),不是逐字符背代码。
- 判据:合上教程能写出**逻辑正确、能跑通**的一版,哪怕命名和细节与原版不同,即算成功。API 记不住可查,逻辑串不起来才是没吃透。
- 对应"伪闭卷"警惕:背代码文本是假复刻,理解逻辑重建才是真复刻。

### 3. 复习(对抗遗忘)

- 每个系统复刻通过后记一条**复刻卡片**:核心逻辑 3-5 句概括 + 当时卡在哪。
- 间隔重复:隔几天不看卡片,凭记忆重述这个系统怎么实现。重述不出 → 回去**重刻**(不是重看)。
- 逼的是回忆不是再认,比重看笔记有效。

### 4. 项目架构自复盘

- 项目做完画一张**架构图**(手画即可):有哪些系统、各自职责、系统间依赖和数据流。
- 对每个系统问三个 why:为什么这样设计?去掉会怎样?换种写法代价是什么?答不出 = 架构层没吃透。
- 这张图 + 这些 why = 面试讲项目的底稿。

**来源**:学习模式调整会话。随实操逐条细化或替换为更适配用户的版本。

## 方法论

### 档案B · 新增 · 需求分解自问清单(闭卷前自推,替代"被引导")

**定位**:解决"拿到需求脑中无步骤流、需外部推"的缺口(见档案D场景01)。**非记忆具体解法(那是临摹),是练通用分解能力。** 闭卷前自问,把"Claude推"内化为"自推"。

**五问(可迁移任何需求)**:
①**终点产出是什么**：这个需求最后要产出什么?(mesh→要能显示的网格)
②**终点需要哪些零件**：要得到这个产出,必须先有哪几样东西?(网格→顶点+三角形+赋值)
③**零件间谁依赖谁(定顺序)**：哪个必须先有、哪个依赖前面的?(三角形依赖顶点先算出来→所以顶点在前)
④**每个零件本身怎么拆**：逐个拆,这个零件本身又要哪几步?(顶点→循环+sin/cos+z递推)
⑤**卡住回到哪一步**：哪一层没想清?

**用法**:每次闭卷/复刻前,先走五问、**自己写出步骤流(哪怕错/漏)再动手**;写出的是自己拆的,不是给的。动手验证→错了回来改拆解。练几次内化成"拿到需求自动过一遍"。

**禁**:背某个具体任务的步骤序列(换需求即废)。练的是"怎么开始拆",不是"这个项目怎么做"。

**来源**:实战·全域摸底会话(用户自主发现"无步骤流、需人推"缺口并要求解法)。

### 新方法论:"例子锚定 → 推导区别 → 无提示复述"三步法

**定位**:专治"辨析类知识点(A vs B:接口/抽象类、类/结构体、值/引用、List/Dictionary……)靠表格死记、一描述就没概念"。替代"背对比表"。核心:**用一个能推导的例子当锚,让区别变成推出来的、而不是背下来的;再用无提示复述练提取通道。** 三步缺一不可——前两步解决"理解",第三步解决"调得出"。

**第一步 · 造例子,不背定义。** 学 A vs B 时,不准先抄"A 是…B 是…"的对比表。先各给 A、B 一个**最小具体例子**,例子要能体现它"典型用在什么场景"。

> 例(类 vs 结构体):
> 
> - 结构体例子:`struct Vector3 { float x,y,z; }`——一个"纯数据、量小、到处拷贝也无所谓"的东西。
> - 类例子:`class Player { int hp; ...一堆方法 }`——一个"有身份、要被多处引用、不希望被拷贝"的东西。
> 
> 先有这两个画面,不碰任何"区别列表"。

**第二步 · 从例子主动推导（推性质/行为/区别）**：盯着例子，把这个知识点的性质/行为/区别 一条条推出来。每条都要能从例子推出，推不出的那条 = 还没真理解那条。从原理推，不从文本搬。

> 承上:
> 
> - Vector3 是纯数据、量小 → 值类型(拷贝走,不用堆分配)→ **所以结构体是值类型**(不是背的,是"纯小数据当然按值拷贝最划算"推出来的)。
> - Player 有身份、要被多处共享引用 → 引用类型(大家指向同一个)→ **所以类是引用类型**。
> - 由"值类型"这一条,又能推:结构体传参是拷贝(改了不影响外面)、结构体没有 null(它是值)……
> - **一个"值 vs 引用"的锚,推出下面一串区别。** 这就是你说的"反推区别",但关键是从**原理**反推,不是从表格搬。

**第三步(你漏的、最关键的)· 过几天,无提示复述。** 前两步做完当天你会觉得"懂了"——但那还是再认(例子和推导都在眼前)。**隔 2-3 天,合上一切,拿张纸,从零把这个辨析讲一遍**:先默出那两个例子,再从例子推区别,一路推下来。

> - 推得出来 → 提取通道通了,这个点真拿下。
> - 卡住 / 推不动 → **别翻表格,回去重看你那两个例子**(不是重背区别)。因为卡住说明你锚点没扎牢,补锚点,不是补结论。
> - 重复到某次能无提示一路推完。

**为什么第三步不能用"多写代替"**:写代码时你被眼前的结构/报错/笔记提示着,是再认;第三步要的是**零提示从脑子里调**,这是唯一能练"提取通道"的动作。你手上熟练度靠多写(对),但"合上能讲出来"只能靠无提示复述——两条腿,分别练。

**和"以写代记"的分工(把你的方子摆到正确位置)**:

- 你说的"做项目撞到结构就停笔分析、翻笔记、多写"——**保留,它管"手上熟练度 + 加深理解",是对的**,继续做。
- 但它管不了"提取通道",那块交给第三步(无提示复述)。
- 所以不是二选一:**写代码练手(你的方子)+ 无提示复述练提取(补上的)= 两条腿走。** 你的方子没错,只是它一条腿,我给你补上另一条。

**关于你说"刻意记有压力、低效"**:对,别"刻意背"。但第三步的"无提示复述"**不是背**——背是"反复看直到记住文本",复述是"合上从理解重新推出来"。前者痛苦低效(你历史上就吃这个亏),后者是"检验+巩固理解",本质是主动回忆,不是记忆。你排斥的"刻意记"应该排斥;第三步不是那个东西,别把它俩混了。

## 错点复习卡(收口即沉淀 · 通用 · 不随 internalize 撤除)

**定位**:长期复习纪律,区别于"复刻方法论脚手架"(后者 internalize 后撤,这条不撤)。任何阶段性任务(摸底 / 模块拆解 / 概念答疑 / 复盘 / 模拟面试……)收口时,把本轮错点用「错了什么 → 正确是什么」一句一条固化进 Obsidian 复习清单,间隔重复时回取。对冲档案 A 行为缺口"学过不回头"——错误不沉淀,同一处会再错。

**Claude 动作(主动)**:阶段 / 里程碑收口时主动评估本轮是否有值得记的错点,有则产出。**用户不得不开口要 = 漏了。** 但过"是否值得"这关——没真错点的一轮不硬凑。

**格式**:一错一行,`错答 X → 正:Y`。一句话讲清"错在哪 + 对的是什么";完整解释留在对话里,清单只做索引 + 提醒。

**只收真错,以下不列(防污染)**:

- 依赖视角 / 环境的滑标签(如顺 / 逆时针哪面是正面)→ 记操作规律("面看不见就翻绕序"),不算错点。
- 低频 API 语法(如 Vector3 用圆括号)→ 查文档即可,非缺口(见档案 A 根源 2)。
- 正确讲完后的自我怀疑 → 虚惊非错,直接测或中性确认(见指令规则 6)。

**与复刻卡片(本档第 3 条)的关系**:复刻卡片沉淀**成功**(通过后核心逻辑 + 卡点),错点卡沉淀**错误**(这轮错了什么);两者都进复习清单,间隔回忆一起回取。

**来源**:实战 · 全域摸底会话。用户主动提出并要求推广到任意对话(不限摸底);方法论归用户所有,Claude 采纳固化。
