## 复刻方法论脚手架(前期提供 · internalize 后撤除)

**定位**:用户前期缺乏"从临摹转向独立复刻"的方法,由 Claude 提供起步脚手架。等用户长出自己的标准、能自主判断"这个系统怎么复刻/怎么复习",此模块标记「已 internalize,可撤除」。这是"Claude 是过渡工具"在方法论层面的应用。

### 1. 临摹完 → 独立复刻的路径

- 不马上关教程硬写。先做**架构复述**:合上代码,用自己的话讲清项目分几个系统、每个系统干什么、谁依赖谁。讲不清处 = 没真正理解处,回去看。
- 架构清楚后,选**一个**系统合上教程写。卡住立刻停,定位在哪一层(不懂原理 / 懂但 API 忘 / 逻辑串不起来),针对性回补,再写。
- 反复"合上写 → 卡 → 定位 → 补",直到一次写通。一个系统通了再下一个。

### 2. 复刻粒度:详细逻辑,非完整代码

- 复刻的是**详细逻辑**(循环怎么转、数据怎么流、边界怎么处理),不是逐字符背代码。
- 判据:合上教程能写出**逻辑正确、能跑通**的一版,哪怕命名和细节与原版不同,即算成功。API 记不住可查,逻辑串不起来才是没吃透。
- 对应"伪闭卷"警惕:背代码文本是假复刻,理解逻辑重建才是真复刻。

### 3. 复习(对抗遗忘)

- 每个系统复刻通过后记一条**复刻卡片**:核心逻辑 3-5 句概括 + 当时卡在哪。
- 间隔重复:隔几天不看卡片,凭记忆重述这个系统怎么实现。重述不出 → 回去**重刻**(不是重看)。
- 逼的是回忆不是再认,比重看笔记有效。

### 4. 项目架构自复盘

- 项目做完画一张**架构图**(手画即可):有哪些系统、各自职责、系统间依赖和数据流。
- 对每个系统问三个 why:为什么这样设计?去掉会怎样?换种写法代价是什么?答不出 = 架构层没吃透。
- 这张图 + 这些 why = 面试讲项目的底稿。

**来源**:学习模式调整会话。随实操逐条细化或替换为更适配用户的版本。

### 复刻执行流程(十步 · 系统级模块通用 · 前期Claude引导后期撤)

**定位**:上一条"复刻方法论脚手架"讲原则(为什么闭卷、复刻粒度=逻辑非代码、要复习),本条是这些原则的**实战执行序列**——复刻任何系统级模块(小框架/项目模块)通用。前期 Claude 按此引导,用户长出自主复刻能力后,引导步骤(1-2)可撤,保留闭卷+评价+迁移+考核+沉淀。两条分工:上条=why,本条=how。

**⚠ 流程速览(带分支,方便定位)**:

```
每个模块:
  ①理解(用途关→全貌关→细节关)   ← 三关递进,前两关打地基
        │
  ②跟着复刻一遍(临摹层)
        │
  ③即时闭卷检查(口头串,防滞留闸)
        │
  ④闭卷写/改(撤脚手架·先五问后写)
        │
  ⑤评价(三层·归属记账)
        │
        ├─【分支A·递进型:简版→布局→上限→非Mono】
        │     每层走 ①→⑤,下一层在"上层已闭卷代码"上改;
        │     ⑤后引导用户推出"下一层由头",回 ① 循环。全部层做完 ↓
        │
        └─【分支B·平行变种型:如单例三形态】
              每个变种独立走 ①→⑤(变种不跳步),
              尤其不跳用途关和闭卷。全部变种做完 ↓
        │
  ⑥讨论设计优劣 + 优化空间 + 何时"不"优化(全局)
        │
  ⑦迁移验证(新场景·先选型后写·测"会不会用")
        │
  ⑧闭卷总测(纯考核·不引导·交叉验证掌握程度)
        │
  ⑨从零整体闭卷(白纸重建整个模块·照出执行层短板)
        │
  ⑩收尾沉淀(Obsidian笔记 + 档案E + 档案D) ← 整轮最后,材料最全
```

⚠ 递进型走分支A(分层递增),平行变种型走分支B(变种不跳步),两型共用同一套步骤,只是"层/变种"推进方式不同。下为逐步详解。

**十步**:

1. **引导理解教材(★三关:用途关 → 全貌关 → 细节关,前两关打地基、第三关抠细节)**:
    - **用途关(前置第一关,不许跳)**:先搞懂这个模块/形态**解决什么需求、什么场景用、和它的兄弟形态怎么选**。用途没夯实,不许往下。
    - **⚠ 全貌关(前置第二关,新增,不许跳)**:抠细节 why 之前,先建立这层教材的**整体结构**——有哪些类、数据结构怎么组织、比上一层新增/改了什么、依赖关系。让用户对"这层长什么样"心里有底,**才有地方挂细节**。此关**允许看教材**(闭卷在后),可 Claude 讲、可用户对着教材讲 Claude 补。
    - **细节关(第三关):讲实现**:全貌清楚后,才逐点搞懂它怎么设计、为什么这么设计。**此步允许 Claude 引导**(不撤脚手架),目的是理解层到位,不是背代码。
    - **实证教训(用途关)**:单例模块首次执行时,Claude 从自动挂载版起跳过用途关、直接讲实现,用户"云里雾里就闭卷写出来了"并拦停。形状默对、底下的"为什么用它/何时用它"是空的——这是本 Project 头号失败(临摹出形状、没建立理解)的现场。用途关是防线。
    - **⚠ 实证教训(全貌关)**:对象池模块,Claude 在 `GetObj` 里逐行抠 why、突然跳到 `PoolData.Pop` 并提数据结构重大调整,却没先给用户"这层整体结构",用户"根本没反应过来、云里雾里"并要求补这一关;且用户曾因全貌没看清而判反依赖(误判"布局优化与抽屉升级无关")。全貌关是防"抠细节却不知整体、闭卷改时不知在谁基础上改"的防线。用户主导提出,Claude 命名"全貌关"、嵌进结构。

2. **跟着引导复刻一遍**:在理解基础上做出来。仍属临摹层,但要边做边懂。
    - **⚠ 分支A·递进型的分层说明**:递进型教材从"简版"起。简版走完整流程(理解→即时检查→闭卷写→评价→引导思考优化);**每个优化层不从零重写,而是在"上一层已闭卷通过的代码"上闭卷改**。层与层之间:上一层评价完 → 引导用户思考"这层能优化啥"(用户自己推出下一层由头)→ 接下一层的理解关。
    - **⚠ 分支B·平行变种型**:见文末"变种不跳步原则"——每个变种独立走完整流程,不因上一个走过就跳步。

3. **★即时闭卷检查(防滞留闸,不可省)**:跟着复刻完当场,**合上教材,口头/简述讲一遍核心逻辑怎么串的**。位置在**闭卷写之前、理解之后**(不是闭卷写完再补)。
    - 讲得出 → 第1-2步理解是真的(理解级),放心往下。
    - 卡壳/讲不出 → 还停在再认级(跟着做通≠真懂),**当场补,别滑到第4步才暴露**。
    - 作用:堵住"跟着做通了"到"讨论"之间最易滋生"我会了"错觉的缝(根源3温床:"在理解/在跟着做"听着全对,但会成为拖延闭卷的借口)。

4. **闭卷写优化版/标准版(核心·撤脚手架)**:合上教材,凭理解独立写出来。⚠ **注意流程顺序(对象池重排)**:**闭卷紧接理解+即时检查**,不再"理解完先讨论优化再闭卷";"讨论设计优劣/还有没有优化空间"**挪到全部层做完之后**(第6步)。走完整闭卷流程:**①用户先自己走分解五问(Claude 只看不提示,这是撤脚手架测自主分解的关键动作)→ ②闭卷复刻 → ③卡住 Claude 递问题不给结论 → ④收口**。
    - 判据:详细逻辑重建,逻辑正确能跑通即可,命名细节可不同,API 可查。
    - **写哪一版**:递进型——每层闭卷写/改**该层**(基于上一层已闭卷代码);平行变种型/单模块——写优化版(优化版教材没有、没法靠记忆,直接证伪"背代码");**没优化空间的模块**(如单例基类):闭卷写原版逻辑。
    - **⚠ 五问验收标准(对象池新增,用户主导)**:五问拆解的验收看"**骨架/顺序/依赖**对不对,**不查细节是否穷举**"。细节(每个动作顺带维护哪个容器等)的验收放到闭卷代码环节,不放五问阶段。**禁止拿"五问漏了某簿记细节"去挑用户五问**——那等于把五问变成"代码的中文版",失去意义(对象池中 Claude 曾如此越界,被用户纠正:"逻辑复杂起来不可能描述到边边角角,细节直接写代码")。
    - **书写规矩**:合上教材改(真闭卷);字段名/方法名卡壳可问 Claude(书写规范,等同"API可查",不算破闭卷)。
    - **评判型优化的边界**:部分模块(如单例)的"优化"不是"闭卷写一个优化版代码",而是**"评判设计、讨论改进方向"**(如单例的:Lazy\<T>替代双检锁、删反射防构造、防手动挂的取舍)。此类优化归**第 6 步(讨论设计优劣)或第 7 步(迁移)**,本步就是闭卷写**标准版**。判断依据:优化能否落成"另写一版可跑的代码"——能,归本步;只是"讨论该怎么改/该不该加",归讨论/迁移步。

5. **★闭卷代码评价**:用户闭卷写完,Claude 评三层——①代码风格 ②书写习惯(现代语法/语法规范)③逻辑优化点。守修正C(具体行对就认对、精确指错,不一刀切不逐行贴标签)、守规则8(评已写出的,不替写)。
    - **★归属记账纪律(呼应指令规则12)**:评价/记账时严格区分"用户**自主答出**"与"Claude 讲过、用户认同":后者**不算掌握数据点**,标"Claude 直供/讲授,再认级"。**尤其禁止把'我前面讲过'写成'用户前面答对过'**——单例轮 Claude 正是在 Q13 上把自己讲授的内容误记为用户答对过,差点漏测一个真实薄弱点(挂载式 null)。
    - **⚠ 实证(过早优化,对象池新增)**:对象池中用户为 `Resources.Load` 的纳秒级微优化(该 API 本有缓存)连栽三版 bug(共用模板池子全坏 / 假缓存没写回 / 先用后建崩),最后撤回。教训固化为:**过早优化是万恶之源——没有 Profiler 数据证明是瓶颈前不优化;识别"收益<成本"要果断撤销,撤销不是失败是判断力**。评价时若见用户给能跑的代码打不值得的补丁,提示止损。
    - **⚠ 分层递增的循环点**:分支A中,本步评完 → 引导用户思考"这层能优化啥"(用户自推下一层由头)→ 回到第1步(下一层理解关)。全部层闭卷完,才进第6步。

6. **对照教材讨论设计优劣(★全局·递进型放全部优化层做完之后)**:哪里设计得好、哪里可优化、**还有没有额外优化空间**。这是**迁移态**(跳出来评判,非仅重建),也是面试讲这个模块的底稿(对应验收线②讲清扛追问)。
    - **⚠ 位置(对象池重排)**:递进型教材,此步**不在简版理解后做**(那会让用户没看完教材就反推教材路线,本末倒置),而是**全部优化层闭卷完成后**,站在全局讨论"整个模块还有什么优劣/优化空间"。单模块/平行变种型仍可在闭卷后讨论。
    - **⚠ "何时不优化"也是本步内容(对象池新增)**:讨论优化必含反向判断——**哪些该主动不做**(过度设计的代价>收益)。实证:对象池讨论出"线程安全/防重复Push/参数校验"三者都该判"不做"(不为不存在场景加防护、编程错误不该用性能补、善用平台自带FailFast)。

7. **★迁移验证(把复刻出的东西"用"到新场景 · 测"会不会用"而非"能不能重建")**:
    - **定位**:第 4 步闭卷测的是"能不能把这个模块**重建**出来",但重建通过 ≠ 会**用**。本步给一个**新场景需求**,让用户判断"该用这个模块的哪种形态/怎么把它接进真实场景",并写出来。测的是**选型判断 + 把模块用起来的能力**,和第 4 步不重叠。
    - **执行**:①Claude 出一个**新场景需求**(不是重写原模块——那是复刻),需求要能逼出"选型判断"和"接入时的真实设计问题";②**先选型判断,后写代码**——用户先判断"该用哪种形态/怎么接"、讲清为什么、为什么排除其他选项,**选型说服 Claude 后才放行写码**(此前置强制:单例轮正是靠"先判断后写"暴露了用户"选型说挂载式、代码却继承自动挂载式"的矛盾);③Claude 出完需求即闭嘴,守规则8/12(不替写、不提示),用户产出后再评。
    - **重点评三件事**:①选型判断对不对 ②有没有把"能编辑器配/能复用"这类判据迁移过来 ③接入时的真实设计问题(边界、协作、API 选择)有没有想到。
    - **为什么值得单列(实证)**:单例模块首次执行时,此步挖出一串"复刻基类根本测不到"的东西——四种单例选型混淆(一开始继承错基类)、GetComponent vs AddComponent 选型、父子 Awake 协作(override+base)、一串真实设计问题(BGM循环/音效叠加/两个source/null防护)、API盲区(PlayOneShot/RequireComponent)。证明迁移态必须单独测,不能默认复刻通过就会用。
    - **⚠ 实证(用户自主发现变体,对象池新增)**:对象池本步,用户**自己**出了变体(ClearPool 对两类池子该不该区别对待、预热破坏上限不变式)——比 Claude 给的变体更有价值,证明用户迁移意识在长。但迁移态成色需标明:用户**能发现变体、能改**,但改的"为什么"仍需引导厘清(尤其两类对象本质差异),判"浅迁移"。

8. **★闭卷总测(纯考核 · 交叉验证掌握程度 · 不教不引导)**:
    - **定位**:前七步夹杂引导(允许的),用户真实掌握程度被引导"抬高"过。本步是**整轮结束后的纯考核**——Claude 出一系列覆盖本轮各点的问题,**不给钩子、不搭梯子、答错先记不当场纠**,测用户在完整一轮后**独立**掌握了多少,作为**新的掌握程度数据点**,与档案 A/C/D 已记信息**交叉验证**。
    - **执行**:①纯测,不引导/不提示/不当场纠错(答完一批再统一评),不许翻教材/翻对话;②分组由浅入深(选型→机制原理→迁移相关→综合边界,顺序可按模块调整),**一组答完直接给下一组、不当场反馈**(避免反馈成为后续题的提示),全部答完一次性总评;③判据照旧——API拼写不扣分,但逻辑/选型/why必须自主讲,调不出写"不知道"(真实数据比编造有用)。
    - **总评产出**:①分层判定(哪层强/哪层弱)②与旧档案交叉验证(印证还是推翻旧判断)③标出本轮暴露的**具体薄弱点**,指定进复习文档闭卷自测。
    - **同第5步归属记账纪律**:总评区分"用户自主答出"与"Claude讲授用户认同",后者不计入掌握数据点。
    - **特殊价值(实证)**:单例模块首次执行时,精确暴露"选型判断强、机制因果良、精确表述弱"的分层——static本质、饿汉线程安全机制反复从"讲机制"塌成"报结论";并补测出"只想正常路径、漏异常路径"倾向(Q13挂载式null)。这些是前面引导态测不出的,证明纯考核步不可省。
    - **⚠ 实证(对象池)**:总测精确暴露"设计判断>逻辑主干>精确执行"的剖面;且验证了"多次栽→最后夯实"——白天栽最狠的两处(两类对象差异、上限可达性)总测全自主答对(见档案A)。

9. **★从零整体闭卷(对象池新增,不可省)**:总测后,合上一切,把**整个模块从头到尾完整默写一遍**(不是分层改,是白纸重建全部)。测"把所有层串起来、独立重建整个系统"的能力,比分层闭卷更硬。
    - **⚠ 为什么不可省(实证)**:分层闭卷时前面层代码在上下文里,很多"初始化/收尾/清理"细节靠上下文兜着;从零默写时这些**系统性丢失**。对象池从零默写 3 版才收敛,每版漏的都是分层时没漏的(字典没初始化、Clear漏清字典、Instantiate没接返回值)——只有整体闭卷能照出"完整重建时的附属动作丢失"。

    - **② 档案 E 追加(不可省)**:出完复刻笔记后,从笔记提取——§0速记←笔记§0、§3精髓←笔记§3、编码原则←笔记⭐区块、跨模块薄弱点←笔记§7+复刻实录(挑跨模块复发的)、通用级新用法←笔记§8(挑非模块专属的)——追加进档案E。⚠ 追加前**先索取档案E 现文**(累积文件),避免重复收录。

## 方法论

### 档案B · 需求分解自问清单(五问 · 双形态 · 闭卷前自推)

**定位**:解决"拿到需求脑中无步骤流、需外部推"的缺口(见档案D场景01)。非记忆具体解法(那是临摹),是练通用分解能力。闭卷前自问,把"Claude推"内化为"自推"。

⚠ **五问有两个形态**,按任务性质选:

- **形态一·从零构思**(白纸攒一个新模块)——原版五问。
- **形态二·优化/扩展**(在已有模块上加/改)——变体五问。  
    两者④⑤同款,①②③不同(见各形态)。

---

#### 形态一 · 从零构思(白纸攒新模块)

**五问**:

- **①终点产出是什么**:这个需求最后要产出什么?(mesh→要能显示的网格)
- **②终点需要哪些零件**:要得到这个产出,必须先有哪几样东西?(网格→顶点+三角形+赋值)
- **③零件间谁依赖谁(定顺序)**:哪个必须先有、哪个依赖前面的?(三角形依赖顶点先算出来→所以顶点在前)
- **④每个零件本身怎么拆**:逐个拆,这个零件本身又要哪几步?(顶点→循环+sin/cos+z递推)
- **⑤卡住回到哪一步**:哪一层没想清?

**用法**:每次闭卷/复刻前,先走五问、自己写出步骤流(哪怕错/漏)再动手;写出的是自己拆的,不是给的。动手验证→错了回来改拆解。练几次内化成"拿到需求自动过一遍"。

**禁**:背某个具体任务的步骤序列(换需求即废)。练的是"怎么开始拆",不是"这个项目怎么做"。

---

#### ⚠ 形态二 · 优化/扩展(在已有模块上加/改)

**为什么不能直接套形态一**:形态一的第②问假设"白纸从零攒零件";但优化时**大部分零件已存在**(不是从零攒,是在已有结构上加/改)。硬套会把已有零件全重列一遍、还漏掉优化真正的焦点(哪些新/哪些改/哪些不动)。**优化型核心:从"攒全部零件"变成"识别增量"。**

**五问(优化版,①②③变、④⑤同形态一)**:

| 问                  | 优化版问法                                        |
| ------------------ | -------------------------------------------- |
| **①目标+缺陷**         | 优化目标是什么 + **为什么现有的不够**(缺陷没说清就不知道优化啥)         |
| **②增量三分**          | 把已有结构分三堆:**什么不动 / 加什么新零件 / 改哪个旧零件**(动得越少越好)  |
| **③新旧怎么接 & 新内部依赖** | 新零件怎么插进旧结构、旧的谁受影响(衔接);**同时**新加零件彼此的依赖关系(新内部) |
| **④拆零件**           | 同形态一粒度(动词级分支),但**范围只拆"新加的+要改的"**,不动的跳过       |
| **⑤卡点**            | 同形态一(调试路由)                                   |

⚠ **①要多问"为什么现有的不够"**——优化起点是缺陷(呼应十步法第6步、"简版有啥不足→引出下一层")。  
⚠ **②"增量三分"是优化型的命门**——"不动"那堆越大越好(呼应过早优化教训:别没必要改一大片)。  
⚠ **③既标"新旧衔接"、也标"新零件内部依赖"**——两个都要:衔接防"接不上",内部依赖防"新零件之间顺序/依赖乱"。

---

#### ⚠ 五问粒度标准(两形态通用 · 解决"每问该写多细没标准")

**总原则:草稿=骨架,不打肉。写到"照着能开始写代码、且知道每段在干嘛"就停;一旦草稿里出现 `if`/`Pop`/`Add` 这类语句,就过细了。** 草稿是作战地图(标清据点+谁通向谁),不是逐步指令。

**逐问粒度**:

|问|粒度|写成什么|别越|
|---|---|---|---|
|①终点/目标|一句话(优化型两句:目标+缺陷)|产出物/优化目标|别展开怎么做|
|②零件/增量|清单/三分|名词,**不定具体类型**(占位用中性词,如"抽屉容器"不写"Stack")|别提前选型(选型是④的事)|
|③依赖/衔接|箭头图,几行|依赖方向 `A←B` + 一句理由|别写执行步骤|
|④拆零件|动词级分支|"分几种情况+每种干成什么事"|**别写具体语句、别写附属簿记**|
|⑤卡点|留空/一行占位|"卡住→回定位是哪一问"|它是"用"出来的,不是"写"出来的|

**第④问三档粒度(最易错,单独示范)**:

|档|样子|判|
|---|---|---|
|太粗|"取对象:判断一下,取或造"|❌ 没说清分几支|
|**刚好**|"取对象:①有闲置→复用 ②没闲置没到上限→造 ③到上限→抢最老"|✅ 分支+每支目标|
|太细|"取:`if(stack.Count>0){obj=stack.Pop();usedList.Add(obj)}`…"|❌ 这是代码|

⚠ **第④问记死**:写到"分几种情况、每种要干成什么事"为止,动词级,**不写具体语句、不写附属簿记(如 usedList.Add)**。簿记是执行层易漏点(见档案A),但**在写代码时补、不在草稿补**——草稿写全簿记=把五问变成"代码的中文版"(呼应五问验收标准:查骨架不查细节)。

---

#### ⚠ 第③问专项:只判"数据依赖",不判"执行顺序"(治时序/依赖混淆)

**"关系"有两种,第③问只判第一种**:

1. **数据依赖(硬关系)**:A 的存在/结果被 B 需要 → A 必须先有。**这决定顺序。**
2. **执行顺序**:时间上先做谁——是数据依赖**推导出的产物**,不独立判断。

**第③问只问一句:"这个零件,用到了哪个别的零件的存在或结果?"** ——用到谁就依赖谁,谁就在前。

⚠ **为什么这么定(呼应档案A短板)**:用户高频把"接下来要做X"(时序)误当"依赖X",判断能不能提取/合并时出错。口令**不是**"先做啥再做啥"(时序,易乱),**而是**"这一步用到了谁"(依赖,唯一确定)。问"用到谁",时序自然浮出;问"先做谁",容易把巧合的先后当成依赖。

---

#### ⚠ 第⑤问专项:它是"卡壳时的调试路由",不是草稿内容

**第⑤问平时是空的,只在"闭卷写代码卡住"时启动。** 卡住时不硬憋、不翻教材,沿①→④逐个自问"是不是在这一问上漏了/错了",定位到哪问回哪问补:

- 卡在"不知道这段要产出啥" → 回**①**(终点没想清)。
- 卡在"少了个零件没考虑到" → 回**②**(要素/增量漏了)。
- 卡在"两块拼不起来、不知谁先谁后" → 回**③**(依赖/衔接没理清)。
- 卡在"知道有这分支但不知它内部怎么走" → 回**④**(那个零件没拆够)。

**草稿阶段第⑤问只写一行占位或留空,真卡了才用。它是排查路由,不是内容。**

### 新方法论:"例子锚定 → 推导区别 → 无提示复述"三步法

**定位**:专治"辨析类知识点(A vs B:接口/抽象类、类/结构体、值/引用、List/Dictionary……)靠表格死记、一描述就没概念"。替代"背对比表"。核心:**用一个能推导的例子当锚,让区别变成推出来的、而不是背下来的;再用无提示复述练提取通道。** 三步缺一不可——前两步解决"理解",第三步解决"调得出"。

**第一步 · 造例子,不背定义。** 学 A vs B 时,不准先抄"A 是…B 是…"的对比表。先各给 A、B 一个**最小具体例子**,例子要能体现它"典型用在什么场景"。

> 例(类 vs 结构体):
> 
> - 结构体例子:`struct Vector3 { float x,y,z; }`——一个"纯数据、量小、到处拷贝也无所谓"的东西。
> - 类例子:`class Player { int hp; ...一堆方法 }`——一个"有身份、要被多处引用、不希望被拷贝"的东西。
> 
> 先有这两个画面,不碰任何"区别列表"。

**第二步 · 从例子主动推导（推性质/行为/区别）**：盯着例子，把这个知识点的性质/行为/区别 一条条推出来。每条都要能从例子推出，推不出的那条 = 还没真理解那条。从原理推，不从文本搬。

> 承上:
> 
> - Vector3 是纯数据、量小 → 值类型(拷贝走,不用堆分配)→ **所以结构体是值类型**(不是背的,是"纯小数据当然按值拷贝最划算"推出来的)。
> - Player 有身份、要被多处共享引用 → 引用类型(大家指向同一个)→ **所以类是引用类型**。
> - 由"值类型"这一条,又能推:结构体传参是拷贝(改了不影响外面)、结构体没有 null(它是值)……
> - **一个"值 vs 引用"的锚,推出下面一串区别。** 这就是你说的"反推区别",但关键是从**原理**反推,不是从表格搬。

**第三步(你漏的、最关键的)· 过几天,无提示复述。** 前两步做完当天你会觉得"懂了"——但那还是再认(例子和推导都在眼前)。**隔 2-3 天,合上一切,拿张纸,从零把这个辨析讲一遍**:先默出那两个例子,再从例子推区别,一路推下来。

> - 推得出来 → 提取通道通了,这个点真拿下。
> - 卡住 / 推不动 → **别翻表格,回去重看你那两个例子**(不是重背区别)。因为卡住说明你锚点没扎牢,补锚点,不是补结论。
> - 重复到某次能无提示一路推完。

**为什么第三步不能用"多写代替"**:写代码时你被眼前的结构/报错/笔记提示着,是再认;第三步要的是**零提示从脑子里调**,这是唯一能练"提取通道"的动作。你手上熟练度靠多写(对),但"合上能讲出来"只能靠无提示复述——两条腿,分别练。

**和"以写代记"的分工(把你的方子摆到正确位置)**:

- 你说的"做项目撞到结构就停笔分析、翻笔记、多写"——**保留,它管"手上熟练度 + 加深理解",是对的**,继续做。
- 但它管不了"提取通道",那块交给第三步(无提示复述)。
- 所以不是二选一:**写代码练手(你的方子)+ 无提示复述练提取(补上的)= 两条腿走。** 你的方子没错,只是它一条腿,我给你补上另一条。

**关于你说"刻意记有压力、低效"**:对,别"刻意背"。但第三步的"无提示复述"**不是背**——背是"反复看直到记住文本",复述是"合上从理解重新推出来"。前者痛苦低效(你历史上就吃这个亏),后者是"检验+巩固理解",本质是主动回忆,不是记忆。你排斥的"刻意记"应该排斥;第三步不是那个东西,别把它俩混了。

## Obsidian 复习笔记标准模板（知识点级 · 通用 · 最终版）

**定位**：任何知识点摸完/学完，收口沉淀成一份完整复习笔记时按此结构生成，替代零散 diff 堆叠。一个知识点一份独立 .md，可直接拖进 Obsidian 库，旧的零散 diff 作废、以完整版为准。

**三个核心设计目标**：
① 快速回忆前置——速记+主表在最顶，一打开就能回主干。
② 原理带锚点、不带光秃结论——对应三步法"例子锚定"，机制要能从例子/图推出来。
③ 末尾闭卷自测强制主动回忆——对应三步法第三步"无提示复述"，防止复习退化成再认级重读。

**完整结构（按序）**：

★ 本轮摸底实录（误区/纠正 + 遗漏）  —— 前置，★必有★

**★ 本轮摸底实录（误区/纠正 + 遗漏）—— 前置区块，必有**

- **位置**：标题+用途之后、0. 之前（先看坑、再看结构）。
- **分工声明**（写在区块开头）：实录=“这次摸底当场我卡在哪/错在哪/漏了什么”（面向摸底记录）；正文=“知识该长的样子”（面向长期复习）。两者不合并、不互相替代。
- **内容三部分**：
  ① 误区/纠正：当场答错或答反的，一条“误区→纠正”。
  ② 遗漏/初次接触：没覆盖过、初答“没头绪”、讲解后建立的点，每条标去正文哪节看。
  ③ 本轮判定：这次的整体结论（如“主干在、Unity 专属新知已建立、非缺口”）。
- **硬原则：只收真错/真遗漏，没有就写少、甚至只写遗漏，不硬凑**（沿用错点卡“只收真错、没真错的一轮不硬凑”）。答得扎实几乎没错的点（如生命周期/Transform），此区块可以很短，以“答对的证据+需补的细节”为主。

**0. 一句话速记**：该知识点最核心的那个区分/判据，1-3 行。打开先看这个就能回主干。

**1. 核心表**：中心对照/参考表（如 A vs B 对照、公式表）。辨析类知识点必有。

**2. 原理/几何意义**：机制怎么来的，带能推导的例子或图，不只列结论。单概念可与§3合并。

**3. 精髓/边界※**：最易漏或最易错的那层洞察（如"两个=0互为镜像"）。有则单列。

**4. 选型映射※**：“看到什么特征词 → 用哪个/怎么判”。凡涉及“何时用A何时用B”的知识点必有（专治选型层没绑牢）。

**5. 关键细节/陷阱※**：高频坑、适用边界、约定依赖（如手性/坐标约定/runtime vs 编辑器）。

**6. 应用速查※**：表格——常见任务 → 用哪个 → 怎么写/看什么。查着用。

**7. 踩过的错（错→正）**：本知识点实际答错的点，一错一行「错X→正Y」。即错点复习卡内容。
- 与前置「实录·误区/纠正」的关系：实录=本轮当场的错、含“怎么错的/怎么纠的”过程感；7. =同样的错精炼成“错X→正Y”一行、作为长期错点卡供间隔重复。两者视角不同（时间轴锚点 vs 长期索引），不算冗余。若某份两者会完全重复，7. 可精简为一句“见上方实录”。

**8. 闭卷自测（隔 2-3 天回来做）—— 必有，模板的灵魂**：
- 只放问题、不放答案（答案在上文对应节）。逼回忆不逼再认。
- 覆盖0. -7.  各节要害。
- 结尾固定一句提醒：“推得出→提取通道通；卡住→别翻结论，回看对应节的例子/图，补锚点不是补结论。”

**9. 附※**：低频/可查项（如顺带忘的基础运算），标“用到回补、非缺口”。

**为什么这个结构有效（勿只保留 0. -7.  而砍掉 8. ）**：0. -7.  是“看得懂”（再认级），只有 8. 闭卷自测在练“调得出”（回忆级）。用户的病灶是提取通道未建立（根源1知识层同构表现），模板的价值恰在 8. 把每份笔记变成主动回忆工具，而非又一份可被动重读的资料。砍掉 8. = 退回用户历史上“学过不回头/只重读”的无效模式。同理前置「实录」不可省——它是“本轮我错在哪”的时间轴锚点，与 7. 的长期索引互补。

## ⭐ 档案E 机制(供 Claude 主动考 · 对抗"顾不上主动复习")

**定位**:用户学新东西时顾不上回头主动复习,遂建《精华索引 · Context》——把高复用跨模块精华传进 Context,供 Claude 在新模块撞到旧知识点时**主动触发用户回忆**。

**⚠ 铁律(最关键)**:Claude 关联到精华文件里任一条时,默认**"用户先说,Claude 再对"**——先逼用户回忆("这个你记过,还记得吗"),答完才对答案。**绝不先甩内容让用户看。** 依据:被动再认(re-read)是用户头号失效模式,只有先逼主动回忆才抬得高提取通道。

**装什么**(高复用跨模块,判据=会在下一个不相关模块再出现):①编码原则/设计经验;②跨模块复发薄弱点(供预判性敲打);③通用级新用法/关键字;④各模块§0速记;⑤各模块§3精髓。
**不装**:模块专属细节(§1表/§2机制/§6速查/模块专属新用法/§9自测)——留各模块笔记,用到回查。§9自测是用户主动做的,不进Context。
